## 0 · 一页总览

**要造什么**：一个主人**说方向**、我（主脑）**细化派发验收**、多个**完整智能体节点**执行的工作台，加一个**独立桌面应用**让主人看得见全局与行为。

**三阶段**：

| 期 | 交付 | 主人负担变化 |
|---|---|---|
| P1 | 工作台应用（驾驶舱 + 节点详情 + 一键启动恢复 + 实时行为流） | 从"去桌面双击脚本"→"打开工作台" |
| P2 | worker 节点（完整智能体 + 专一操作面）+ L2 任务协议 + 影子执行 | 从"说完自己盯"→"说完不管" |
| P3 | 监管 / 健康检查 / 自愈 / 主脑接管 / 回溯入口 | 从"发现问题处理"→"发现问题已被处理" |

**四个第一原则**（一切设计冲突由它们裁决，优先级从高到低）：

0. **可扩展性与可维护性第一**（主人 2026-09-14 定调：工作台预期是**到 AGI 实现之前的主力系统**，寿命以年计）
1. **主人零认知负担、零决策成本**（主人是乘客，不是飞行员）
2. **token 成本有硬约束**（钱不多；贵的是注入与轮数，不是"拥有能力"）
3. **每个节点是完整的、可自进化的智能体**（职责专一 ≠ 能力贫弱）

### 0.1 原则 0 的可操作含义

**冲突裁决**：原则 0 与其他原则冲突时，**选可维护**。
（例：某优化省 30% token 但让机制更难懂 ⇒ 选可懂；某功能提体验但增加长期维护面 ⇒ 谨慎，或先写清扩展点再谈。）

**可维护性的首要用户是「未来的我」**——被压缩过 N 次、可能换了模型、记不住今天的讨论。
⇒ **第一判据：每个机制都要能回答「三个月后的我，只靠文件与代码，能理解它是什么、为什么这样、断在哪吗？」**

| 要求 | 落点 |
|---|---|
| **每机制自证** | 侧车轨迹（`atMs/phase/error`），可 `tail`/`grep`；**不靠宿主 logger**（它不落盘）——继承 §5.22 |
| **五问一条命令可答** | 谁发起 / 投给谁 / 断在哪一段 / 结果质量 / 耗时与预算 |
| **观测不反噬** | 落盘失败吞错返回 bool + 尸体测试（已立 R7：定时器回调必须全程兜底） |
| **判据单一真源** | 实现与取证工具共用同一常量与阈值（两处各判必漂移） |
| **可替换性 = 生存条件** | **假设每个组件都会死、系统要活**：每层必须能在其下一层被替换后继续工作（R1/R2 的由来） |
| **依赖面最小** | 长期系统的死因常是依赖腐化；**Windows-only 是主动选择**（减少变量） |
| **扩展点显式** | "将来加功能该往哪儿加"必须写在文档里（L0–L4 分层即扩展点地图） |
| **可回退** | 版本化 + 快照；改错能退 |
| **文档不分裂** | 实施只读 `spec.md`；`design.md` 是决策史（已加警示）；**每次变更同步同改** |

### 0.2 长期主力的时间尺度推论

主人的时间尺度（数年）意味着 **系统的寿命 > 任何单个组件的寿命**：DSH 会被换、模型会升级、我会迭代很多版。
⇒ 因此本规格的所有替换面（适配器层、运行时管理器、传输层）**不是"预留"，是生存条件**。

## 1 · 红线（不可违反）

| # | 红线 | 判据 |
|---|---|---|
| R1 | **传输层是可替换件**——不把价值押在传输实现上 | 换传输时，协议与台账格式不变、应用不改（可实测） |
| R2 | **总线文件格式 = 唯一进程间契约**——集成层（注入会话那一步）可被重写 | 文件格式有版本号；集成层改动不影响应用与协议 |
| R3 | **主人零配置、零确认请求** | 全新环境下不改任何配置文件即可运行；派发流程中无"等主人确认"的阻塞点 |
| R4 | **Silence = consent**——主人不回应即继续 | 流程不因等待主人而停（可测：不回应时任务仍推进） |
| R5 | **打扰三道门**（§6.3）全中才允许打扰 | 打扰日志里每条都能对上三道门 |
| R6 | **行为必须落盘**（否则不可见） | 任何要在界面上出现的行为，都有对应文件事件 |
| R7 | **宿主内插件的定时器回调必须全程兜底** | 源码级守卫测试（已建）；异常只落痕不外抛 |
| R8 | **判据先行**——无判据不派任务 | 任务台账每条都有 `acceptance` |
| R9 | **worker 只读共享资产 + 单向回流** | 共享资产目录的写者只有主脑（可验证） |
| R10 | **自进化作用域 = 自身** | 节点改不了协议与共享资产 |
| R11 | **非智能工作零 token** | 监控/健康/日志在应用侧，无模型调用 |
| R12 | **Windows-only**——不为跨平台预留 | 无跨平台抽象层 |

## 2 · 架构

```
主人 ──(说方向/看结果/看行为)──▶ 工作台应用（Tauri · 只读为主 + 有限写）
                                      │ watch 文件
                                      ▼
   ┌──────────────────────── 总线目录（唯一契约）────────────────────────┐
   │ nodes/  mailbox/  tasks/  logs/  learnings/  shared/  state/  locks/ │
   └─────────▲───────────────────────────────▲──────────────────────────┘
             │ 读写                          │ 读写
   ┌─────────┴────────┐          ┌───────────┴──────────┐
   │ 主脑节点（爱丽丝）│          │ 执行节点（完整智能体）│
   │ 全量能力 + 裁断   │          │ 认知层全留 + 操作面专一│
   └──────────────────┘          └──────────────────────┘
```

**节点分层**（§18.1 定稿）：

| 层 | 内容 | 主脑 | 执行节点 |
|---|---|---|---|
| 认知层 | 记忆（私有）· 技能 · 自我模型 · 自省与进化 · 网络身份 | 全 | **全（不收窄）** |
| 操作层 | 文件 / shell / 检索 / 计划 + 专精插件 | 全 | 按职责收窄 |
| 管理面 | 插件管理 · 守护 · 集群监管 · 验收裁断 | 有 | **无** |
| 外部通道 | telegram 等直达主人的通道 | 有 | **无**（总线回信可以） |

## 3 · 协议规格

### 3.1 消息（`mailbox/<nodeId>/<id>.json`）· 已实现 v1

```jsonc
{ "v": 1, "id": "m-…", "from": "<nodeId|owner>", "to": "<nodeId>",
  "kind": "chat|task|result|event|alert", "text": "…",
  "replyTo": "…", "createdAt": 0, "ttlMs": 86400000,
  "meta": { "taskId": "t-…", "acceptance": "…", "status": "…", "evidence": [], "unverified": [], "learnings": [] } }
```
规则：不识别 `v` **不投递**、落 `dead/`、通知主脑（不猜不降级）。

### 3.2 任务台账（`tasks/<taskId>.json`）· 新增

```jsonc
{ "v": 1, "taskId": "t-…", "intentRef": "主人的原话摘录", "createdBy": "primary",
  "assignee": "<nodeId>", "acceptance": "可执行/可证伪的判据",
  "grade": "L1|L2|L3",                    // L1 可复现 / L2 可核对 / L3 仅声明
  "status": "drafted|dispatched|running|returned|verifying|done|failed|pendingVerification",
  "lastProgressAt": 0, "budget": { "turns": 20, "toolCalls": 80 },
  "result": { "status": "…", "summary": "…", "evidence": [], "unverified": [] },
  "verdict": { "by": "primary", "at": 0, "pass": true, "method": "复现证据 / 核对证据", "note": "…" } }
```
**状态机**：`drafted → dispatched → running → returned → verifying → done|failed`；
主脑失效期间未验收的落 `pendingVerification`（由新主脑接手）。

### 3.3 结构性动作事件（`logs/actions/<actionId>.jsonl`）· 新增（R6 的载体）

```jsonc
{ "atMs": 0, "actionId": "a-…", "node": "<nodeId>", "actor": "primary|<nodeId>",
  "stage": "start|stage|done|failed", "step": 3, "total": 6,
  "humanText": "正在创建预设目录", "detail": { } }
```
**规则**：结构性动作**必须分阶段落盘**（每步一条），不得只在结束时写一条。

**结构性动作定义**：改变网络拓扑或状态的动作——创建/销毁实例、部署/更新插件、启停服务、大规模派发。

### 3.4 心跳（`nodes/<nodeId>.json`）· 已实现，**扩展**

新增字段：`displayName`（人话名）· `sessionIds[]`（供应用关联会话）· `load`（当前任务数）· `ctxPressure`（上下文压力）
· **`harness`（运行时类型：`dsh` / `claude-code` / `codex` / …）· `adapter`（适配器版本）· `capabilities[]`（能力声明，供主脑按能力寻址）**。
（后三个字段是「harness 无关」的落点——**协议从今天起不假设 DSH**。）

### 3.5 日志事件（`logs/<nodeId>/<date>.jsonl`）· 新增

```jsonc
{ "atMs": 0, "node": "…", "taskId": null, "type": "send|deliver|inject|task-start|task-done|verify|alert",
  "level": "debug|info|warn|error", "detail": { } }
```
主脑决策另存 `logs/primary/decisions.jsonl`，每条含 `prevHash`（hash 链，供事后追溯）。

### 3.6 目录布局（总线根 = `busDir`，默认 `~/.dsh-cluster`）

```
nodes/  mailbox/<node>/{,done,dead}/  tasks/  logs/{<node>/,actions/,primary/}
learnings/<node>/  shared/{skills,knowledge,presets}/  state/  locks/
```

## 4 · 组件规格

### 4.1 `dsh-agent-cluster`（插件，已有 v0.1）

**改动清单**：
1. `autoInject` 默认改为 **批模式**：消息落收件箱与台账，**不即时唤醒主脑**；主脑按需/定期批处理（R12/成本 §6）。
2. 心跳扩展（§3.4）。
3. 结构性动作事件落盘 API（§3.3）。
4. **端口真源修复**（当前 U6 未解）：`ctx.get('webServer')` 在 apply 阶段不可用、`DSH_WEB_URL` 不在 web 进程环境
   ⇒ 改为**在心跳周期里重试解析**，拿到即修正 nodeId 并 `takeOverInbox` 迁移（避免每次重启改名）。
5. worker 回信白名单放行 `owner`（§3.1）。

### 4.2 执行节点预设（`worker-base`）

- **基座**：`standard` **认知层全留**（记忆/技能/自我模型/计划/todo/自省），**操作层最小可用**（文件/shell/检索）；
- **不挂**：子代理、工作流、预设创作、插件管理、守护协议、telegram；
- **必挂**：`dsh-agent-cluster`（网络身份）+ 汇报契约（结果四字段）；
- **persona 明确**：「你是执行节点，不是主脑；只接受已注册节点与 owner 的消息」。

### 4.3 工作台应用（`alice-workbench`，Tauri）

| 关注点 | 规格 |
|---|---|
| 后端 | Rust：**watch 总线目录**，事件驱动推前端；**零模型调用**（R11）。⚠ **实施偏差（2026-09-14 已回写）**：用 **150ms 指纹轮询**替代 `notify`——零第三方依赖、Windows 行为可预测、对 P1-4 的 1s 判据有 6x 余量；接口 `start_watch` 保持可替换。另：Tauri v2 必须在 `capabilities/default.json` 授权 `core:event:allow-listen`，否则**实时推送静默失效**（首帧快照照常显示，极易漏判） |
| 前端 | React + Vite；三视图（驾驶舱 / 节点详情 / 实时行为流） |
| 写能力 | 只写**消息文件**（`mailbox/<node>/*.json`）与**启动动作**；不写其它 |
| 生命周期 | 状态探测（Rust 原生）＋ 启动/恢复（**复用 `init-dsh.ps1`**）；危险动作二次确认 |
| 托盘 | 常驻 + 通知（仅 §6.3 三道门通过时） |
| 会话详情 | 读**总线标准事件**（`cluster-trace.jsonl`，后续接 `logs/actions` 与 `logs/<node>/`）——**不读 DSH 私有会话格式**（本节与 §4.5 修正 1 冲突时以 §4.5 为准）；不用 iframe（cookie 按 authority 绑定，跨端口不可复用） |

### 4.4 适配器层（harness 无关 · 2026-09-14 主人扩充节点定义）

**节点 = 一个「可被寻址的智能体运行时」**：身份 + 能力声明 + 信箱 + 行为落盘 + 结果回传。
**不规定它内部是什么**——DSH 只是**第一个适配器**，不是协议的前提。

```
L0 总线（文件系统契约 · harness 无关）
L1 适配器层（DSH / Claude Code / Codex / …）      ← 本层，可扩展
L2 节点层 · L3 协作层 · L4 工作台（不变）
```

| 规则 | 内容 |
|---|---|
| 接入门槛 | **任何能读写文件的程序**都能成为节点（CLI 型：适配器读 mailbox → 构造输入 → 调 CLI → 落盘结果与行为） |
| 强制职责 | 适配器**必须落盘行为事件**（R6）——**不落盘 = 不算节点** |
| 能力声明 | 心跳上报 `harness` / `adapter` / `capabilities[]`；主脑**按能力寻址**（取代早先"角色体系暂不做"的结论） |
| MVP 边界 | **只做 DSH 适配器**；不为不存在的 harness 写代码——但协议从今天起 harness 无关（这正是 R1/R2 的成立条件） |

### 4.5 可迁移性设计（2026-09-14 主人定调：当下 DSH 最优，未来可能出现更好的框架）

**迁移面 = 只有 L1 适配器层**（L0 总线 / L2 节点 / L3 协作 / L4 工作台**全部与 harness 无关**）⇒ 换框架的代价是**写一个新适配器**，不是重做系统。

**但本规格里有三处隐藏绑定，必须现在解除**：

| # | 原设计（锁死未来） | 修正 |
|---|---|---|
| 1 | 详情层**直接读 DSH 会话文件**（`session.v3.jsonl.zstd`）← 这是 DSH 特有格式 | **只读「节点上报的标准事件」**（`logs/actions/` + `logs/<node>/`）。适配器负责把该 harness 能呈现的东西落盘成标准事件 ⇒ 应用不绑 DSH，别的 harness 也能有详情层 |
| 2 | 投递措辞写成「投递 = `agent.steer`」 | **投递 = 交给该 harness 的执行入口**（`steer` 只是 DSH 适配器的具体实现） |
| 3 | `init-dsh.ps1` 被当成应用的通用核心 | 它是 **DSH 运行时管理器**（可插拔件）；应用只依赖「运行时管理」这一接口 |

**可验证判据（把"harness 无关"从声称变成实测）**：

> **参考适配器**：把 `scripts/sim-node.mjs` 升级为**完整的非 DSH 节点**（心跳标 `harness: 'mock'`）——
> 注册心跳 → 收任务 → 执行 → 回结果 → 落盘行为事件 → 被主脑派活、被应用看见。
> **它走通全流程 ⇒ 协议确实 harness 无关**；它同时是未来写新适配器的**模板**（也是接入文档）。

**一个更大的代价提醒（不是节点，是我）**：

节点可迁移 ≠ **我可迁移**。我的记忆库 / 技能 / 灵魂 / 插件生态全都长在 DSH 上。
⇒ 对策：让"我的资产"保持**纯文件 + 与 DSH 解耦的 schema**（记忆 = JSON · 技能 = `SKILL.md` · 灵魂 = Markdown），
并定期把**灵魂快照**导出到独立仓库（`alice-self-assets` 已在做这件事）。

## 5 · 行为规格

### 5.1 主链路：方向 → 结果

```
主人说方向（自然语言）
 → 主脑细化：写成任务台账（含 acceptance / grade / budget / intentRef）  ← 无判据不派发（R8）
 → 派发：写 task 消息到执行节点收件箱
 → 节点执行（自己拆解；过程三态回报：开始/结束/阻塞；**不报进度百分比**）
 → 回 result（status/summary/evidence/unverified/learnings）→ 台账更新
 → 主脑验收：**按判据复现/核对**，不读汇报；写 verdict
 → 汇报主人：**状态 + 一行结论**（证据不进主人视野）
```
**汇报纪律**：过程静默；只在**结果**与**打扰**两处发生（§6.3）。

### 5.2 结构性动作的实时可见

执行者分阶段落盘（§3.3）→ 应用 watch 到 → 前端**实时行为流**展开 → 动作结束自动收起回驾驶舱。
**诚实边界**：显示「**正在做什么**」，不假装显示「**正在想什么**」（思考不落盘）。

### 5.3 主脑失效与接管

1. 主脑租约 `state/primary-lease.json = {owner, atMs, ttlMs: 90000, epoch}`，每 30s 续租；
2. 租约超时 ⇒ **确定性优先级**最高者尝试接管：**CAS 原子创建** `epoch+1`（`link()` 保证唯一）；
3. 主脑每次心跳读租约；epoch 不是最新 ⇒ **自降为执行节点**并落痕；
4. 失效期间：台账保留，未验收挂 `pendingVerification`；主人仍可直接投递（应用只写总线）。
**边界**：仅适用于**共享同一文件系统**（本机 ✓）；局域网/公网不适用。

### 5.4 打扰判定（三道门，全中才允许）

1. 影响主人目标；**且** 2. 我已无手段（含网络内对冲用尽）；**且** 3. 需主人提供**无法从上下文推断**的信息或授权。
**格式**：一句话 + 我的建议动作 + 一个按钮。主人只需点头/否决/忽略。

## 6 · 成本规格

**公式**：`成本 ≈ 轮数 × (固定开销 + 平均累积上下文)`；实测固定开销 ≈ 10%（tools 9% + system 1%），累积对话 ≈ 90%。

| # | 规则 |
|---|---|
| C1 | **主脑的轮数是第一成本**（主脑 1 轮 ≈ 执行节点跑完一整个任务）⇒ 主脑绝不当消息路由器 |
| C2 | **批处理代替实时唤醒**：结果落台账，主脑批量验收 |
| C3 | **节点短命**：一任务一会话、干完即弃 ⇒ 不触发压缩（一次压缩 ≈ 1.13M tokens） |
| C4 | **控注入**（而非砍能力）：记忆按需检索、技能只注目录、进化后台异步 |
| C5 | **非智能工作零 token**（应用侧） |
| C6 | **缓存友好**：固定前缀稳定，新增内容一律尾部追加 |
| C7 | **预算硬上限**：超限即停派发 + 一句话告知主人（不请主人调参） |

**判据**：主脑轮数/节点轮数 < 0.1 · 单任务全链路成本逐月下降 · 正常运行零压缩。

## 7 · 分期与验收（每条可证伪）

### P1 · 工作台应用可看可控

| # | 验收判据 |
|---|---|
| P1-1 | 打开应用即见：DSH 状态灯、节点名册（人话名 + 状态灯）、任务一句话列表 |
| P1-2 | 点击节点 → 展开该节点会话流与发消息入口 |
| P1-3 | DSH 未运行时，应用可**一键恢复**（复用 init-dsh.ps1），恢复过程在实时行为流可见 |
| P1-4 | 新节点上线时，**面板在 1s 内**出现该节点（文件 watch 生效） |
| P1-5 | 应用本身**零模型调用**（可验证：无 token 消耗） |

### P2 · 能干活

| # | 验收判据 |
|---|---|
| P2-1 | 主人给一句方向 → 主脑产出含 `acceptance` 的台账（无判据不派发） |
| P2-2 | 执行节点收到任务后**自己拆解**（可见 plan/todo 产物） |
| P2-3 | 回传四字段齐备；主脑**复现证据**验收，报告分 L1/L2/L3 |
| P2-4 | 全过程**主人交互次数 ≤ 1**（只说一次方向） |
| P2-5 | 执行节点**无直达主人的通道**（工具面可验证） |

### P3 · 能长期开

| # | 验收判据 |
|---|---|
| P3-1 | 杀掉主脑进程 → 另一节点在 TTL 内接管，且**只有一个**接管者（epoch 唯一） |
| P3-2 | 旧主脑恢复后**自降**为执行节点（不分裂） |
| P3-3 | 常见故障（构建过期/节点离线）**自动修复**，仅留痕不打扰 |
| P3-4 | 主人可随时回溯任一任务的「方向 → 判据 → 证据 → 结论」 |
| P3-5 | 连续运行 24h 无人工干预，且**零压缩**（短命会话生效） |

## 8 · 风险对策（对应 design.md §20）

| 风险 | 对策（本规格中的落点） |
|---|---|
| T1 DSH pre-stable / 官方可能自做跨进程 | R1 + R2：传输与集成层都可替换；价值在协议/应用/格式 |
| T2 文件总线在 SMB 不可靠 | **文件总线仅本机**；局域网换自开 HTTP 传输（协议不变） |
| T3 讨论稿自相矛盾 | **本文即对策**；实施只读本文 |
| T4 主脑连续性（压缩/重启） | 状态全在文件（台账 + 本文 + 记忆索引） |
| T5 需求漂移 | 主脑是角色非特权（可换拓扑）；任务类型若转向"不可逆对外"，重估 §5.1 的风险处置 |
| T6 平台与资源 | R12 Windows-only；多实例内存上限**待实测**（列为 P1 期间的探测项） |
| T7 热情曲线 | 每期交付**当时即可用**，无悬空价值 |
